# DSH 进度汇报插件

`dsh-progress-fold` 是一个独立的 DeepSeek Harness（DSH）插件。长任务执行期间，插件引导助手在完成明确步骤或一轮探索后简短汇报，遇到影响方案的歧义时先向用户确认。回合成功结束后，配置过的 DSH 原生「对话」页会把中间正文和工作详情收进最终答案上方的「用时」入口，展开后可以回看。

## 安装与配置

克隆仓库后，在根目录用 PowerShell 打包，再把归档安装到 `desktop` profile。启用新插件，停用 Better Display 和 Progress Rules，然后回到原生「对话」页。 [DSH 插件安装说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md)

```powershell
npm pack --pack-destination $env:TEMP
dsh plugin --profile desktop add (Join-Path $env:TEMP 'dsh-progress-fold-0.2.0.tgz')
```

默认连续 5 个静默工具步骤后提醒一次，并要求输出可见正文再继续调用工具。在当前 profile 的 `cordis.patch.yml` 里覆盖 `dsh-progress-fold` 的配置即可调整阈值。`everySteps` 填正整数。`enforce: false` 关闭步骤提醒和工具限制，系统提示词仍会引导模型分阶段汇报。

```yaml
- id: dsh-progress-fold
  config:
    everySteps: 5
    enforce: true
```

## 进度如何产生

1. 通过 DSH 的系统提示词服务注册两条工作规则。长任务每完成一个明确步骤或一轮探索，用 1–3 句正文说明做了什么、得到什么结果、接下来做什么。遇到影响方案的歧义、须由用户决定的偏好，或查不到且猜错代价高的事实，先向用户确认。短任务可直接回答，连续的小操作可以合并汇报。
2. 通过 `agent/pre-step` 检查同一回合上一个已完成的模型步骤。一个步骤可以有多次工具调用，只计一次。步骤有工具调用、但没有非空的用户可见正文时计为一次沉默。默认连续满 5 步，在下一次获准进入的模型请求中加入一条简短提醒。
3. 提醒后，若模型仍在没有可见正文的情况下调用工具，DSH 会在执行前拦截并说明原因。模型可以输出正文后重试。直接调用的 `ask_user_question` 可以继续执行。在 PTC 模式中，`run_code` 也受此限制，模型可先用正文说明进度或待确认的问题，再通过 `run_code` 调用工具。
4. 计数按会话和回合隔离，同一个步骤最多计一次。有可见正文或步序不再连续时清零，新回合从零开始。等待进度期间只发一次提醒。提醒带插件来源标记，在会话中作为上下文呈现。

工具限制只检查该步有没有非空正文。正文是否提供了有效进展、是否有必要向用户确认，仍由模型判断。进度走原生文本流，单次模型调用或工具执行期间的等待状态由 DSH 显示。

## 「对话」页的折叠设置

在 DSH Desktop `0.2.2-rc.5` 中文界面中，打开「设置 → 通用设置」，在「字号大小」下方找到以下选项。

| 设置 | 推荐值 |
| --- | --- |
| 工作步骤展示 | 标准（Standard），也可以选详细（Detailed） |
| 工作步骤收起时机 | 回答结束后（On completion） |
| 收起后显示的回复 | 仅最终回答（Final answer only） |

正常回合结束后，阶段回复随过程折叠。失败和停止的回合保留整轮过程；待审批时可继续查看当前状态。用户在过程开始后插入消息时，DSH 保留消息与过程的顺序，该轮仍可按组展开和收起。缺少轮次起点的历史记录按原生规则显示，有完整起止时间的回合可以显示用时。 [DSH 原生整轮折叠说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/packages/client/ui-chat/src/client/conversation-nodes/README.zh.md#整轮折叠)

## 验收

已在 DSH `0.2.2-rc.3` 的隔离 headless profile 中验证归档安装和提示词加载。用本地模拟模型执行前 5 个静默步骤后，DSH 发出一次提醒，拦截第 6 步的两个工具调用和第 7 步的静默调用，并在第 8 步出现正文后恢复执行。

1. **验证触发边界。** 检查前 5 个静默步骤的工具正常执行，第 5 步后提醒一次。忽略提醒时，同一批工具及后续静默调用会被拦截。输出正文后恢复执行并重新计数。另验证直接提问、独立会话、回合切换、取消和关闭限制的情况。
2. **验证桌面体验。** 只启用新插件运行短任务和长任务。长任务在最终回答之前出现进度，完成后答案上方有可展开入口，重新打开历史会话仍可回看。检查中断、待审批和执行中追加消息时的显示。
